## What is TechNexusOrg?

TechNexusOrg operates official open-source repositories where students can find curated, real issues, reserve them through an active claim system, receive genuine code reviews from experienced maintainers, and build a permanent **Contributor Passport**.

### Core Product Principles:
1. **GitHub Evidence is the Source of Truth:** Every verified credential, level promotion, and passport record links directly to official GitHub merge events, commit SHAs, and pull requests.
2. **Quality Over Spam:** We reward legitimate problem-solving, test coverage, and code quality. Trivial typo PRs or copy-pasted solutions are rejected.
3. **Realistic Engineering Workflows:** Contributors use real Git branching, issue closing syntax (`Fixes #123`), and GitHub code review threads.
4. **No False Promises:** We do not claim employment guarantees or instant jobs. We provide real engineering experience that speaks for itself.

## 👨‍💻 Never Contributed to Open Source Before?

That is completely okay. Everyone started with their first commit.

Here is the essential vocabulary you need:
- **Issue:** A problem, bug, or feature documented by maintainers that needs to be addressed.
- **Pull Request (PR):** Your proposed code changes submitted to the repository for review.
- **Code Review:** Feedback provided by repository maintainers to verify code standards and test coverage.
- **Merge:** The acceptance and integration of your code into the project's official codebase.

You do not need to be an expert. Read the issue description carefully, choose an issue labeled `good first issue` or `beginner`, and ask questions when you hit blockers.

## 🛠️ Your First Pull Request Tutorial

Here is the standard workflow to contribute to any TechNexusOrg repository:

```bash
# 1. Clone your fork of the repository
git clone https://github.com/<your-username>/<repo>.git
cd <repo>

# 2. Create a descriptive feature branch
git checkout -b fix/issue-123

# 3. Implement your changes and verify tests pass
npm install
npm test
npm run typecheck

# 4. Commit your changes
git add .
git commit -m "fix: resolve issue #123"

# 5. Push your branch to GitHub
git push -u origin fix/issue-123
```

Then open a Pull Request on GitHub with a clear summary:

```markdown
## Summary
Resolves issue #123 by handling null inputs.

## Testing
- npm test passed
- npm run typecheck passed

Fixes #123
```

### ⚠️ Contribution Etiquette
- Never submit fake or generated code without understanding it.
- Never inflate activity with meaningless commits or cosmetic whitespace changes.
- Read `CONTRIBUTING.md` before coding.
- Respect maintainers' time during code review.

## 🏆 The Founding 1,000

The **Founding 1,000** cohort honors the first 1,000 contributors who complete and merge a legitimate pull request on official TechNexusOrg repositories.

- Registration alone **never** reserves a slot.
- Membership is awarded automatically and sequentially (1 to 1000) upon your first verified PR merge.

## ⏱️ Your First 60 Minutes

Follow this practical checklist when starting:
- **First 10 minutes:** Connect your GitHub account and complete onboarding profile.
- **Next 10 minutes:** Read your recommended issue and understand its scope.
- **Next 10 minutes:** Read the repository's `CONTRIBUTING.md` guidelines.
- **Next 20 minutes:** Fork, clone, install dependencies, and run tests locally.
- **Final 10 minutes:** Inspect the code path and plan your implementation.

Do not rush into opening a PR just to get a number. Quality and understanding come first.
